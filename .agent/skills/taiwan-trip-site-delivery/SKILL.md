# 台灣旅程網站交付

先取得完整起訖日期、目的地、成人數、兒童年齡、預算、交通方式、住宿需求與限制。任一必要資料不明時，列出缺口並停止；不得補日期、旅客數、營業時間、路程或預約狀態。

## 收斂流程

1. 分別取得官方活動、景點／交通營運事實、住宿與餐飲品質訊號；每筆動態事實保留來源 URL、提供者、`retrieved_at`、狀態與適用日期。評價和趨勢只影響軟性排序，官方資料決定硬性限制。
2. 先以現有研究、規劃、最佳化與驗證邊界產生唯一行程資料。未知路程不能當成零；未知、過期或衝突的營業時間不可排入餐期；有重大驗證錯誤的旅程不可宣稱可出發。
3. 產生網站時只走既有網站發布器：以 `python3 -m src.cli plan-site` 從完整需求建立 `trips/<trip-id>/trip.json`、`web/public/trips/requested/<slug>/public-bundle.json` 與 `web/public/trip-registry.json`；已有唯一行程資料與網站設定時使用 `scripts/build_trip_site.py`。不要另寫一套靜態頁面或跳過旅程目錄。
4. 公開資料包只能包含公開必要行程、導航、預算與來源資訊；不得包含 provider raw payload、憑證、私人訂房資料或絕對本機路徑。每個可點擊官方頁和地圖連結須實際開啟驗證。
5. 建置前端網站並在桌機與手機實際檢視每日行程、住宿、預約、餐飲、預算、導航與驗證／來源時效。提交前執行適用的測試、型別檢查、格式檢查、建置與公開連結檢查。

## 交付狀態

輸出唯一行程資料路徑、公開資料包路徑、旅程網址、驗證結果、每個未確認事項與下一次重查時間。資料仍會變動時標示為預覽；只有來源新鮮、沒有重大驗證錯誤且公開資料審查通過時才可標示可出發。台灣資料來源或時區未被既有流程支援時，先回報缺口並建立資料轉接或資料契約工作項目，不可以日本假設或估算資料偽裝成功。
